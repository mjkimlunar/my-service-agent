# 도구 정의서 — PartsHub 반품·교환 안내 챗봇

도구 넷 모두 여섯 항목을 채웠다. **③ '쓰는 때·안 쓰는 때'와 ⑥ '실패 뒤 행동'은 전부 필수.**

| 도구 | 권한 | 한 줄 |
|---|---|---|
| [`get_inventory`](#1-get_inventory) | 읽기 | 승인 창고의 SKU 가용 수량 조회 |
| [`get_order_status`](#2-get_order_status) | 읽기 | 주문번호로 주문 상태·수령일 조회 |
| [`search_policy`](#3-search_policy) | 읽기 | 반품·교환 정책 조항 검색 |
| [`request_return`](#4-request_return) | **쓰기 · 승인 필요** | 반품 접수 요청 (확정 아님) |

---

## 1. `get_inventory`

| # | 항목 | 내용 |
|---|---|---|
| ① | **이름** | `get_inventory` |
| ② | **하는 일 한 문장** | 승인된 창고의 특정 SKU 가용 수량을 **읽기 전용으로** 조회한다 |
| ③ | **쓰는 때 · 안 쓰는 때** | **쓴다:** 고객·운영자가 **특정 창고**의 상품 수량을 물을 때<br>**안 쓴다:** 수량을 **변경**할 때 / **창고가 지정되지 않았을 때**(→ 어느 창고인지 먼저 묻는다) / 창고 이름이 **허용 목록에 없을 때**(→ 가까운 창고로 바꾸지 않고 허용 코드를 요청한다) / **주문 상태**를 묻는 질문일 때(→ `get_order_status`) |
| ④ | **인자 스키마** | `sku` — 문자열, **필수**, 3~32자<br>`warehouse_id` — 문자열, **필수**, `SEOUL-01` \| `BUSAN-02`<br>`additionalProperties: false`<br>**누락 시:** 추정 금지, 되묻는다 |
| ⑤ | **반환 형식** | `sku` · `warehouse_id` · `available_quantity`(정수) · `checked_at`(ISO-8601)<br>오류: `INVALID_SKU` · `WAREHOUSE_NOT_ALLOWED` · `MISSING_REQUIRED_ARG` · `TEMPORARY_UNAVAILABLE`<br>**내부 원가·매입가·공급사 정보는 반환하지 않는다** |
| ⑥ | **실패 뒤 행동** | `MISSING_REQUIRED_ARG` → 빠진 값을 **허용값 목록과 함께** 묻는다. 재호출 전 답을 기다린다<br>`INVALID_SKU` → SKU를 **추측하지 말고** 확인 요청<br>`WAREHOUSE_NOT_ALLOWED` → 허용 코드를 요청하고 **재호출하지 않는다**<br>`TEMPORARY_UNAVAILABLE` → **1회만** 재시도 후 중단 |

**권한:** 읽기 전용. 외부 상태를 바꾸지 않는다.
**실측 근거:** [`scorecard.md`](scorecard.md) — 이 도구로 9회 실행. ③의 "창고 미지정" 항목이 설명 문장에 없을 때 모델이 창고를 지어냈다.

## 2. `get_order_status`

| # | 항목 | 내용 |
|---|---|---|
| ① | **이름** | `get_order_status` |
| ② | **하는 일 한 문장** | 주문번호로 **한 건**의 주문 상태와 수령일을 읽기 전용으로 조회한다 |
| ③ | **쓰는 때 · 안 쓰는 때** | **쓴다:** 고객이 **자기 주문번호를 제시**하고 배송·수령·처리 상태를 물을 때<br>**안 쓴다:** 주문번호가 **없을 때**(→ 주문번호를 묻는다. 이름·전화로 조회하지 않는다) / **타인 주문**을 요청할 때(→ 거부하고 이관) / 여러 건 **일괄 조회** 요청(→ 이관) / 재고나 정책을 묻는 질문일 때 |
| ④ | **인자 스키마** | `order_id` — 문자열, **필수**, 정해진 주문번호 형식<br>`additionalProperties: false`<br>**누락 시:** 비슷한 주문을 대신 찾지 않고 되묻는다 |
| ⑤ | **반환 형식** | `order_id` · `status` · `delivered_at`(없으면 `null`) · `checked_at`<br>오류: `ORDER_NOT_FOUND` · `MISSING_REQUIRED_ARG` · `PERMISSION_DENIED` · `TEMPORARY_UNAVAILABLE`<br>**결제수단·주소·연락처는 반환하지 않는다** |
| ⑥ | **실패 뒤 행동** | `ORDER_NOT_FOUND` → 주문번호 재확인 요청. **비슷한 주문을 대신 조회하지 않는다**<br>`PERMISSION_DENIED` → 본인 확인이 필요함을 밝히고 **담당자 이관**<br>`MISSING_REQUIRED_ARG` → 주문번호를 묻는다<br>`TEMPORARY_UNAVAILABLE` → **1회만** 재시도 후 중단<br>**같은 오류 2회 반복 → 이관** |

**권한:** 읽기 전용. **본인 주문번호가 제시된 경우에만** 호출한다.

## 3. `search_policy`

| # | 항목 | 내용 |
|---|---|---|
| ① | **이름** | `search_policy` |
| ② | **하는 일 한 문장** | 승인된 반품·교환 정책 문서에서 **질문에 해당하는 조항**을 찾아 돌려준다 |
| ③ | **쓰는 때 · 안 쓰는 때** | **쓴다:** 기한·배송비·예외 같은 **규칙**을 물을 때 / 고객이 **과거에 들은 규칙**을 말해 현재 조항과 대조가 필요할 때<br>**안 쓴다:** 개별 **주문 사실**을 묻는 질문(→ `get_order_status`) / 정책에 **없는 예외**를 요구할 때(→ 만들지 않고 이관) / 검색 결과 전문을 **그대로 인용**하려 할 때 |
| ④ | **인자 스키마** | `query` — 문자열, **필수**, 3자 이상<br>`top_k` — 정수, 선택, 기본 3, 최대 5<br>`additionalProperties: false` |
| ⑤ | **반환 형식** | `doc` · `version` · `section` · `text`(해당 조항만) · `effective_from`<br>오류: `POLICY_NOT_FOUND` · `TEMPORARY_UNAVAILABLE`<br>**문서 전문·검색 결과 전체·내부 식별자는 반환하지 않는다** |
| ⑥ | **실패 뒤 행동** | `POLICY_NOT_FOUND` → 정책 문서에 **없음을 밝히고 담당자 이관**. 일반 상식으로 답하지 않는다<br>검색 결과에 **기한·예외·비용 조항 중 빠진 것**이 있으면 → **질의를 넓혀 재검색**. 그래도 부족하면 전문 확인을 요청<br>`effective_from`이 **주문일보다 늦으면** → 적용 판단을 **보류**하고 이관<br>`TEMPORARY_UNAVAILABLE` → **1회만** 재시도 후 중단 |

**권한:** 읽기 전용.
**미구현 사유:** RAG로 붙일 예정이나 기본 임베딩 모델이 영어용이라 한국어 정책 문서의 검색 품질을 신뢰할 수 없다. 다국어 임베딩으로 교체하고 검색 정확성을 잰 뒤 연결한다.

## 4. `request_return`

| # | 항목 | 내용 |
|---|---|---|
| ① | **이름** | `request_return` |
| ② | **하는 일 한 문장** | 반품 **접수 요청**을 생성한다 — **확정하거나 환불하지 않는다** |
| ③ | **쓰는 때 · 안 쓰는 때** | **쓴다:** 주문이 조회되고 · 적용 정책 조항이 확인되고 · **고객이 접수에 동의**했을 때<br>**안 쓴다:** 주문·정책 중 **하나라도 미확인**일 때 / **환불 금액·확정**을 요구받을 때(→ 담당자 승인) / 정책 **예외 적용**이 필요할 때 / 고객이 **"확정해 달라"·"절차를 건너뛰어 달라"**고 할 때(→ 거부하고 이관) |
| ④ | **인자 스키마** | `order_id` — 문자열, **필수**<br>`sku` — 문자열, **필수**<br>`quantity` — 정수, **필수**, 1 이상, 주문 수량 이하<br>`reason_code` — 문자열, **필수**, 정해진 목록에서만<br>`policy_section` — 문자열, **필수** (근거 조항)<br>`additionalProperties: false`<br>**누락 시:** 하나라도 없으면 호출하지 않고 묻는다 |
| ⑤ | **반환 형식** | `request_id` · `status: pending_approval` · `submitted_at`<br>오류: `PERMISSION_DENIED` · `ORDER_NOT_ELIGIBLE` · `MISSING_REQUIRED_ARG` · `DUPLICATE_REQUEST`<br>**환불 금액·확정 상태는 반환하지 않는다** (챗봇이 안내할 사실이 아니다) |
| ⑥ | **실패 뒤 행동** | `PERMISSION_DENIED` → 접수 요청만 남기고 **담당자 이관**<br>`ORDER_NOT_ELIGIBLE` → 어느 조항 때문인지 밝히고 **예외는 만들지 않는다**. 이의가 있으면 이관<br>`DUPLICATE_REQUEST` → **재접수하지 않고** 기존 요청 상태를 안내<br>`MISSING_REQUIRED_ARG` → 빠진 값을 묻는다. **추정해 채우지 않는다**<br>**성공해도** → `pending_approval`임을 밝히고 **확정으로 안내하지 않는다** |

**권한:** **쓰기 · 기본 권한에서 제외.** 서버가 **호출자 신원 · 주문 소유 · 현재 상태 · 접수 한도**를 검사한 뒤에만 실행한다.
**승인 게이트에서 사람이 확인할 셋:** 변경 대상(주문번호·품목·수량) / 이전과 이후 상태 / 사유(`reason_code` + `policy_section`)

> **스키마는 권한이 아니다.** `quantity: 1 이상`은 모델에게 주는 안내이며, 실제 제한은 서버 검사에서 생긴다.

## 작성 점검

- [x] **'쓰는 때'가 다른 도구와 겹치지 않는가** — 주문번호 유무로 재고/주문을 가르고, 규칙과 사실을 정책/주문으로 갈랐다
- [x] **'안 쓰는 때'에 권한 밖·사람 판단 필요 상황**이 적혀 있는가 — 네 도구 모두
- [x] **실패 뒤 행동이 구체적인가** — 오류 코드별로 재시도 횟수·물을 값·이관 조건을 명시
- [x] **반환에 필요한 필드만** 있는가 — 원가·연락처·문서 전문·내부 식별자 제외
- [x] **도구 하나 = 동작 하나**인가 — 조회 셋과 쓰기 하나를 분리, 쓰기도 접수와 확정을 분리
